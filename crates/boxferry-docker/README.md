# boxferry-docker

BoxFerry's target-only DockerLens semantic adapter maps the neutral `Application`
to inert native requests. This is bounded prerelease consumer preparation, not
completed Docker input, CLI routes, application acceptance or a deployment tool.
Most embedded callers should use the optional `docker` feature of `boxferry`.

`DockerExporter` requires one caller-selected exact reviewed DockerLens target
profile. A BoxFerry numeric version range only filters that profile's Engine
release; it cannot establish native build, API, daemon-mode or capability evidence.
The complete artifact retains the selected context and unresolved prerequisites.
`DockerOutput::bytes()` exposes only requests; use `complete_bytes()` to retain
bind-source, external-resource and destination obligations as well.

Every unmapped or refused field has structured conversion outcomes. Invalid
references, protected non-environment values, and withheld required environment
prevent an apparently complete service artifact. Literal environment output needs
the independent `DockerEnvironmentPolicy::IncludeLiteral` opt-in; default
`Withhold` never discloses values. `Debug` output remains redacted.

Service dependencies are separate typed `DockerDependencyDecision` values with
provenance and explicit approximate outcomes, not Engine startup/readiness fields
or an executor. External-network constraints distinguish absence, false and true.
Relabelled binds retain configured intent and source obligations, not proof of
destination path suitability or SELinux effects. Typed unresolved destination-PIDs
obligations do not admit an otherwise denied capability or establish enforcement.

Native parsing, acquisition, validation, planning, capability evidence and
serialization belong to DockerLens. This adapter opens no socket, writes no file,
executes no request and contains no Docker source/import placeholder.

The six-fixture volume producer and authored Nextcloud/Supabase checks exercise
only the [bounded consumer checkpoint](../../docs/decisions/0081-bounded-docker-target-consumer-preparation.md).
They do not inspect host bind paths, launch containers, qualify all six applications
or demonstrate normal registry compatibility. A test-only exact Lens source
override, when separately authorized, is isolated prerelease evidence and must not
enter published manifests or main. This adapter already has a real published
0.3.0 baseline: ordinary semver checking remains required, with no first-release
waiver or unverified source-compatibility claim.
